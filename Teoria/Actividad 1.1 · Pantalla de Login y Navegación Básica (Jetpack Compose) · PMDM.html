¿Qué vamos a construir?

▾

Vamos a construir la pantalla de acceso (Login) de una aplicación Android: la primera pantalla que ve el usuario y, por tanto, la más determinante a nivel de UX.

Nota previa: se asume que ya sabes crear un proyecto en Android Studio, la sintaxis básica de Kotlin y cómo ejecutar la app en un emulador.

4

Conceptos fundamentales

▾

4.1. ¿Qué es Compose?

Jetpack Compose es el toolkit moderno de Google para construir UIs nativas. A diferencia de XML, donde el diseño se describe en un archivo separado, en Compose la UI se describe con funciones Kotlin que se ejecutan y se recomponen cuando cambia el estado.

XML / Views

Layout en archivo XML separado. UI inflada al arrancar.

✅Compose

UI descrita con funciones Kotlin. Lo usaremos hoy.

4.2. Composables y estado

Un Composable es una función anotada con @Composable. El estado es un valor que, cuando cambia, provoca que la UI se redibuje (se recompone). Usa remember y mutableStateOf.

Composable
Función que describe la UI. Se recompone cuando cambia su estado.
★ Clave hoy
remember { }
Guarda un valor entre recomposiciones. Sin esto, el valor se reinicia.
★ Clave hoy
mutableStateOf
Crea un estado observable. Si cambia, la UI se redibuja.
★ Clave hoy
LaunchedEffect
Se ejecuta al entrar en la composición, y de nuevo si la key cambia.
★ Clave hoy
Modifier
Cadena de modificadores para padding, tamaño, color, etc.
@Preview
Permite ver un composable en el editor sin ejecutar la app.
5

Diseñando la interfaz (LoginScreen.kt)

▾

5.1. Column, Row y Box

En Compose no hay ConstraintLayout como tal. Los contenedores básicos son Column (vertical), Row (horizontal) y Box (superponer). Usaremos Column porque todos los elementos van uno debajo de otro.

  • Modifier.fillMaxWidth(): ocupa todo el ancho disponible.
  • Modifier.padding(16.dp): añade espacio interior.
  • Modifier.verticalScroll(): permite scroll vertical.

5.2. Componentes Material 3

OutlinedTextField es el campo de texto de Material 3. Soporta hint flotante, errores con isError, supportingText e iconos opcionales.

Importante: en Compose, el error se muestra con isError = true y supportingText = { Text(...) }.

Button es el botón de Material 3: se ve mejor y respeta el tema.

5.3. Dependencias: libs.versions.toml

Los iconos que vamos a usar en LoginScreen.kt deben ser referenciados en libs.versions.toml:

libs.versions.toml
[libraries]
	  androidx-compose-material-icons-extended = { group = "androidx.compose.material", name = "material-icons-extended" }

5.4. Dependencias: build.gradle.kts

Y también en build.gradle.kts:

build.gradle.kts
dependencies {
    implementation(libs.androidx.compose.material.icons.extended)
}

5.5. LoginScreen.kt completo

LoginScreen.kt
package com.ejemplo.login

import android.util.Patterns
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.rememberScrollState
import androidx.compose.foundation.text.KeyboardActions
import androidx.compose.foundation.text.KeyboardOptions
import androidx.compose.foundation.verticalScroll
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.Visibility
import androidx.compose.material.icons.filled.VisibilityOff
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.focus.FocusDirection
import androidx.compose.ui.focus.FocusRequester
import androidx.compose.ui.focus.focusRequester
import androidx.compose.ui.platform.LocalFocusManager
import androidx.compose.ui.res.painterResource
import androidx.compose.ui.res.stringResource
import androidx.compose.ui.text.input.ImeAction
import androidx.compose.ui.text.input.KeyboardType
import androidx.compose.ui.text.input.PasswordVisualTransformation
import androidx.compose.ui.text.input.VisualTransformation
import androidx.compose.ui.unit.dp

@Composable
fun LoginScreen(
    onLoginSuccess: () -> Unit
) {
    var email by remember { mutableStateOf("") }
    var password by remember { mutableStateOf("") }
    var emailError by remember { mutableStateOf<String?>(null) }
    var passwordError by remember { mutableStateOf<String?>(null) }
    var showPassword by remember { mutableStateOf(false) }

    val focusManager = LocalFocusManager.current
    val emailFocusRequester = remember { FocusRequester() }

    LaunchedEffect(Unit) {
        emailFocusRequester.requestFocus()
    }

    fun validarEmail(): Boolean {
        val emailValido = email.isNotBlank() &&
                Patterns.EMAIL_ADDRESS.matcher(email.trim()).matches()
        emailError = if (!emailValido) "Introduce un email válido" else null
        return emailValido
    }

    fun validarPassword(): Boolean {
        val regex = "^(?=.*[A-Z])(?=.*[0-9]).{8,}$".toRegex()
        val passValida = regex.matches(password)
        passwordError = if (!passValida) {
            "Mínimo 8 caracteres, una mayúscula y un número"
        } else null
        return passValida
    }

    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(24.dp)
            .verticalScroll(rememberScrollState()),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.Top
    ) {
        Spacer(modifier = Modifier.height(48.dp))

        Icon(
            painter = painterResource(id = R.drawable.ic_launcher_foreground),
            contentDescription = stringResource(R.string.logo_desc),
            modifier = Modifier.size(120.dp)
        )

        Spacer(modifier = Modifier.height(24.dp))

        Text(
            text = stringResource(R.string.titulo_bienvenida),
            style = MaterialTheme.typography.headlineSmall
        )

        Spacer(modifier = Modifier.height(32.dp))

        OutlinedTextField(
            value = email,
            onValueChange = {
                email = it
                if (it.isNotEmpty()) validarEmail()
            },
            label = { Text(stringResource(R.string.hint_email)) },
            isError = emailError != null,
            supportingText = emailError?.let { { Text(it) } },
            keyboardOptions = KeyboardOptions(
                keyboardType = KeyboardType.Email,
                imeAction = ImeAction.Next
            ),
            keyboardActions = KeyboardActions(
                onNext = {
                    focusManager.moveFocus(FocusDirection.Down)
                }
            ),
            modifier = Modifier
                .fillMaxWidth()
                .focusRequester(emailFocusRequester)
        )

        Spacer(modifier = Modifier.height(16.dp))

        OutlinedTextField(
            value = password,
            onValueChange = {
                password = it
                if (it.isNotEmpty()) validarPassword()
            },
            label = { Text(stringResource(R.string.hint_password)) },
            isError = passwordError != null,
            supportingText = passwordError?.let { { Text(it) } },
            visualTransformation = if (showPassword) {
                VisualTransformation.None
            } else {
                PasswordVisualTransformation()
            },
            trailingIcon = {
                IconButton(onClick = { showPassword = !showPassword }) {
                    Icon(
                        imageVector = if (showPassword) {
                            Icons.Filled.Visibility
                        } else {
                            Icons.Filled.VisibilityOff
                        },
                        contentDescription = stringResource(R.string.toggle_password)
                    )
                }
            },
            keyboardOptions = KeyboardOptions(
                keyboardType = KeyboardType.Password,
                imeAction = ImeAction.Done
            ),
            keyboardActions = KeyboardActions(
                onDone = {
                    focusManager.clearFocus()
                }
            ),
            modifier = Modifier.fillMaxWidth()
        )

        Spacer(modifier = Modifier.height(8.dp))

        Row(
            verticalAlignment = Alignment.CenterVertically,
            modifier = Modifier.fillMaxWidth()
        ) {
            Checkbox(
                checked = false,
                onCheckedChange = { /* Estado local */ }
            )
            Text(stringResource(R.string.recordar_sesion))
        }

        Spacer(modifier = Modifier.height(24.dp))

        Button(
            onClick = {
                val emailOk = validarEmail()
                val passOk = validarPassword()
                if (emailOk && passOk) {
                    focusManager.clearFocus()
                    onLoginSuccess()
                }
            },
            modifier = Modifier.fillMaxWidth()
        ) {
            Text(stringResource(R.string.boton_entrar))
        }

        Spacer(modifier = Modifier.height(16.dp))

        TextButton(onClick = { /* Acción */ }) {
            Text(stringResource(R.string.olvidaste_password))
        }
    }
}

Lógica de la pantalla (MainActivity.kt + LoginScreen.kt + HomeActivity.kt)

6.1. Kotlin mínimo necesario

Elemento Uso en esta actividad
val Variable inmutable (no cambia).
var Variable mutable.
by Delegación de propiedades. Permite escribir count en lugar de count.value.
remember { } Guarda un valor entre recomposiciones.
mutableStateOf(...) Crea un estado observable.
Lambdas { } Se usan en onClick, onValueChange, etc.
? (safe call) emailError?.let { ... }: si no es null, ejecuta el bloque.

6.2. MainActivity en Compose

La MainActivity en Compose es simple: hereda de ComponentActivity y usa setContent { } para cargar el composable.

6.3. MainActivity.kt completo

MainActivity.kt
package com.ejemplo.login

import android.content.Intent
import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.compose.material3.MaterialTheme

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            MaterialTheme {
                LoginScreen(
                    onLoginSuccess = {
						// Navegacion clasica con Intent.
                        // NOTA: En proyectos reales con Compose se usaria NavHost.
                        // Aqu¨ª usamos Intent para simplificar.
                        startActivity(Intent(this, HomeActivity::class.java))
                    }
                )
            }
        }
    }
}

6.4. Explicación línea a línea

setContent { ... }

Punto de entrada de Compose. Todo lo que hay dentro se compone.

MaterialTheme { ... }

Aplica el tema (colores, tipografías) a todos los composables hijos.

var email by remember { mutableStateOf('') }

Crea un estado observable con valor inicial vacío. Cada vez que email cambia, el composable se recompone.

LaunchedEffect(Unit) { emailFocusRequester.requestFocus() }

Al entrar en la composición, pide foco al campo de email.

KeyboardOptions(imeAction = ImeAction.Next)

Configura el botón del teclado como Siguiente.

KeyboardActions(onNext = { ... })

Qué hacer cuando se pulsa Siguiente. Movemos el foco al siguiente campo.

focusManager.clearFocus()

Quita el foco y oculta el teclado.

visualTransformation = PasswordVisualTransformation()

Oculta el texto de la contraseña con puntos.

trailingIcon = { IconButton { ... } }

Añade un icono a la derecha del campo (el ojo).

onLoginSuccess()

Callback que ejecuta MainActivity cuando el login es correcto.

Gestión del foco y del teclado

▾
  • KeyboardOptions(imeAction = ImeAction.Next) en el email → el teclado muestra "Siguiente".
  • KeyboardOptions(imeAction = ImeAction.Done) en la contraseña → el teclado muestra "Listo".
  • LaunchedEffect(Unit) { emailFocusRequester.requestFocus() } → el foco inicial va al email.
  • KeyboardActions(onNext = { focusManager.moveFocus(...) }) → navegación entre campos.
  • focusManager.clearFocus() → cierra el teclado al hacer login.

Esto mejora mucho la experiencia de usuario porque permite navegar entre campos sin tocar la pantalla. Pruébalo tú mismo en el simulador de arriba ↑.

Errores comunes y soluciones

▾
Error Causa probable Solución
@Composable invocations can only happen from the context of a @Composable function Llamas a un composable desde fuera de otro composable. Asegúrate de que la llamada está dentro de setContent { }.
Unresolved reference: stringResource Falta el import. Añade import androidx.compose.ui.res.stringResource.
El @Preview no se renderiza El editor se ha quedado colgado. Build > Rebuild Project o reinicia Android Studio.
La UI no se actualiza al cambiar el estado Te falta remember o mutableStateOf. var x by remember { mutableStateOf(0) }.
HomeActivity not found No la has registrado en el Manifest. Añade <activity android:name=".HomeActivity"/>.
El teclado tapa el botón Falta windowSoftInputMode. Añade android:windowSoftInputMode="adjustResize".
La app se ve en blanco setContent { } no tiene contenido. Revisa que LoginScreen() se llama dentro de setContent.
Cannot access 'Column': it is internal Import incorrecto. Usa import androidx.compose.foundation.layout.Column.
Textos aparecen como @string/... No has usado stringResource(...). Cambia "@string/xxx" por stringResource(R.string.xxx).

Accesibilidad

▾

No basta con que se vea bonito. La app debe ser usable por todos:

  • ✅Todo ImageView debe tener contentDescription (para TalkBack).
  • ✅Botones: tamaño mínimo táctil de 48dp × 48dp.
  • ✅Contraste de texto: debe cumplir WCAG AA (4.5:1).
  • ✅Errores: no comunicar solo con color — icono + texto (Material lo hace automáticamente con setError).
  • ✅Prueba con TalkBack: Settings > Accessibility > TalkBack, navega con el teclado.

⭐

Reto 1: Mover el botón "¿Olvidaste tu contraseña?"

▾

📄 LoginScreen.kt⏱ 10-15 min

El enlace está centrado debajo del botón. Queremos que se coloque alineado a la derecha, justo debajo del botón, y que siga viéndose en horizontal.

  • En Compose, dentro de una Column, cada hijo puede sobreescribir la alineación del padre con Modifier.align(...). ¿A qué valor de Alignment lo quieres alinear horizontalmente?
  • Alternativa: puedes rodear el TextButton con una Row que ocupe todo el ancho (Modifier.fillMaxWidth()) y usar horizontalArrangement = Arrangement.End. ¿Cuál de las dos opciones te parece más limpia?
  • Ojo con el Modifier.fillMaxWidth() en el TextButton: si lo pones, el botón ocupará todo el ancho y la alineación interna no se notará. Probablemente quieras quitarlo en este caso.
  • Si en horizontal el botón no se ve, revisa si la Column exterior tiene verticalScroll. Ya debería tenerlo. Si no lo tiene, añádelo

¿Qué aprenderás? A sobreescribir la alineación de un hijo con Modifier.align(...) o con Arrangement.End en una Row. A decidir entre dos formas válidas de hacer lo mismo y razonar cuál es más limpia. A verificar el comportamiento del scroll en horizontal.

⭐⭐

Reto 3: Añadir un icono personalizado en la contraseña

▾

📄 gradle/libs.versions.toml, app/build.gradle.kts, LoginScreen.kt⏱ 20-25 min

Ahora mismo el icono del ojo usa Icons.Filled.Visibility. Queremos cambiarlo por otros iconos de material-icons-extended, por ejemplo un candado.

  • Para explorar iconos disponibles, busca en la documentación oficial de material-icons-extended o en la propia IDE: dentro del código, escribe Icons.Filled. y deja que Android Studio te autocomplete con la lista
  • El sitio donde se cambia el icono es el bloque trailingIcon = { Icon(...) }. Cambia el imageVector por el nuevo icono.
  • No olvides actualizar el contentDescription si el icono cambia de significado. Por ejemplo, si usas un candado, el contentDescription debería ser "Mostrar/ocultar contraseña" igual, porque la acción sigue siendo la misma.

¿Qué aprenderás? A explorar la librería material-icons-extended para encontrar iconos. A mantener el contentDescription coherente con la acción, no con el icono.

⭐⭐⭐

Reto 4: Bloquear el botón hasta que el formulario sea válido

▾

📄 LoginScreen.kt⏱ 30-40 min

Queremos que el botón ENTRAR esté deshabilitado (en gris, sin poder pulsarse) hasta que tanto el email como la contraseña sean válidos. En cuanto ambos sean válidos, el botón se habilita automáticamente.

  • En Compose, un botón se deshabilita con enabled = false.
  • Necesitas un estado derivado: "¿son ambos campos válidos?". Puedes calcularlo con derivedStateOf o simplemente calcularlo en cada recomposición.
  • Cuidado con el caso vacío: Patterns.EMAIL_ADDRESS.matcher("").matches() devuelve false, así que un email vacío no se considera válido. Perfecto para nuestro caso, pero conviene que lo verifiques.
  • Cuidado con la contraseña vacía: regex.matches("") también devuelve false. Bien.
  • Pásalo al botón: enabled = formularioValido.
  • Pregunta para pensar: Al principio, cuando email y password son "", ¿el botón está habilitado o deshabilitado? ¿Es lo que quieres?

¿Qué aprenderás? A usar derivedStateOf para calcular estado a partir de otro estado. A verificar casos límite (campos vacíos). A gestionar el estado del botón según el formulario.

Reto 7: Tema claro / oscuro

▾

📄 Theme.kt, Color.kt, LoginScreen.kt⏱ 45-60 min

La app debe soportar modo oscuro automáticamente: fondos oscuros y textos claros en modo oscuro, y al revés en modo claro.

  • El parámetro darkTheme de MiAppTheme ya viene con isSystemInDarkTheme() por defecto. Eso significa que la app ya detecta automáticamente si el sistema está en modo oscuro. Compruébalo cambiando el modo en el emulador: Settings > Display > Dark theme.
  • El problema es que algunos colores pueden estar hardcoded en tu LoginScreen.kt. Por ejemplo, si has puesto Color.Red en algún sitio, ese color no cambiará con el tema.
  • Busca en tu LoginScreen.kt cualquier uso de Color(...) o Color.XXX. Cámbialo por referencias al tema: MaterialTheme.colorScheme.primary, MaterialTheme.colorScheme.error, etc.
  • Pista sobre Material 3: Los colores comunes del tema son primary, onPrimary, surface, onSurface, error, onError, etc. Cada uno tiene su pareja "on" para el color del texto que va encima.
  • Prueba con TalkBack y contraste: En modo oscuro, comprueba que el texto se lee bien. Si no, es que has usado un color hardcoded que no se adapta.

¿Qué aprenderás? A usar temas y atributos Material 3 en lugar de colores hardcoded, y cómo funciona el modo oscuro.

Reto 8: Navegación con NavHost

▾

📄 MainActivity.kt, Navigation.kt⏱ 60-90 min

Ahora la navegación se hace con Intent. Queremos migrar a NavHost (navigation-compose), la forma recomendada en proyectos Compose modernos.

  • Añade la dependencia androidx.navigation:navigation-compose en build.gradle.kts.
  • Crea un NavHost con dos rutas: "login" y "home".
  • En LoginScreen, en lugar de llamar a onLoginSuccess(), navega con navController.navigate("home").
  • El NavController se obtiene con rememberNavController().

¿Qué aprenderás? A usar NavHost y NavController. A estructurar una app Compose con múltiples pantallas.
